# 09 · 卷积神经网络（CNN）知识卡片

> **本章定位**：面向**图像**的专用网络。解决的核心问题是——**全连接网络会破坏图像的空间结构，卷积怎么把「局部 + 共享」利用起来**。本章含 MNIST 灰度、CIFAR-10 彩色两条实践线，外加数据准备脚本与 `<kbd>历史演进</kbd>` 卡片。
>
> **承上启下**：承接 07/08 的全连接网络；`cnn_evolution.md` 单独展开 CNN 的整条演进史。

## 知识地图

```
CNN
├─ 动机        全连接要 Flatten → 丢掉像素空间关系
├─ 两大优势    局部连接 + 权值共享
├─ 核心层
│   ├─ Conv2D        卷积核滑动；尺寸 = H-K+1；padding='same' 保持尺寸
│   ├─ MaxPooling2D  取局部最大；尺寸减半；带来平移不变性
│   ├─ Flatten       三维特征图 → 一维，桥接到全连接
│   ├─ Dropout       训练时随机丢神经元，防过拟合
│   └─ Dense+softmax 分类头
├─ 设计规律    尺寸倒推法定层数；尺寸减半→通道翻倍
├─ 数据准备    归一化 0~255→0~1；加通道维；四维张量 (N,H,W,C)
├─ 灰度 vs 彩色 通道 1 vs 3；是否手动加通道维；第一层核深度
└─ 训练        编译三件套 + 训练 + 评估 + 可视化
```

## 核心知识点卡片

### 1. 为什么图片要用 CNN

- **全连接的痛点**：必须先把 28×28 展平成 784 维，**上下左右相邻像素的空间关系被彻底丢掉**——而笔画、边缘、拐角恰恰靠空间位置才能识别。
- **卷积的两大优势**

```
局部连接   每个输出只依赖一小块区域 → 天然捕捉局部笔画/边缘
权值共享   同一个卷积核扫遍全图   → 参数量远小于全连接
```

- **参数量对比（直观感受差距）**

```
3×3×1 卷积核提 32 张特征图 = 3·3·1·32 + 32 = 320 个参数
784 维输入接 32 个神经元   = 784·32 + 32  = 25088 个参数
```

### 2. 卷积层 Conv2D

```
filters         卷积核个数 = 输出通道数 = 提取多少种特征
kernel_size     核大小，3×3 最常用（感受野够用、参数少）
                5×5 参数约是 3×3 的 2.8 倍，一般用两个 3×3 替代
padding='same'  边缘补 0，输出尺寸与输入保持一致
activation      引入非线性
不带 padding：输出边长 = 输入边长 - 核边长 + 1
```

### 3. 池化层 MaxPooling2D

```
在每 2×2 区域取最大值 → 宽高各减半
作用：1) 降采样，减少后续计算量与参数量
     2) 提供一定平移不变性（数字稍偏也认得出）
```

### 4. 「尺寸倒推法」定层数（本章重要设计思路）

```
每池化一次，尺寸减半：
    MNIST  28 → 14 → 7 → 3     最多池化 3 次
    CIFAR  32 → 16 → 8 → 4     最多池化 4~5 次
再池化就变 1×1，空间信息全没了，卷积失去意义
=> 卷积块数量存在上限，不是想堆几层堆几层
   （VGG16 能吃 224×224 大图才能堆 16 层；28×28 的 MNIST 堆 50 层纯属浪费）
```

### 5. 通道数的规律

```
尺寸减半 → 通道翻倍（如 32 → 64），保持信息量平衡
浅层学局部细节（边缘/笔画），深层学更抽象的组合特征
```

### 6. 数据准备

```
读入       npz 里存原始 uint8 像素 (N,H,W)，形状视数据集而定
归一化     像素 / 255 → [0,1]（不归一化梯度尺度混乱，训练又慢又不稳）
加通道维   MNIST (N,28,28) 需 [..., np.newaxis] → (N,28,28,1)
           CIFAR (N,32,32,3) 本身已是四维，不用加
四维张量   Conv2D 要求输入 (N, 高, 宽, 通道数)
```

### 7. 灰度（MNIST）vs 彩色（CIFAR-10）：三处不同

```
1) 输入通道数   灰度 1 → 彩色 3（体现在 Input(shape=(H,W,C))）
2) 是否手动加通道维   MNIST 要补成 1 通道；CIFAR 自带宽高通道
3) 第一层卷积核深度   灰度核 3×3×1=320 参数；彩色核 3×3×3=896 参数
   ⚠ 只有第一层受影响！第二层起输入通道数由“上一层 filters”决定，
     与原始图片通道数无关，所以后续代码写法完全一致
```

- **为什么流程能一样**：Conv2D 做的是三维卷积（高、宽、通道），对通道方向加权求和后压成一张二维特征图——灰度是「1 通道求和」，彩色是「3 通道求和」，机制无区别。

### 8. 参考网络结构

```
MNIST：  Input(28,28,1) → Conv32 → Pool → Conv64 → Pool → Conv64
         → Flatten → Dropout(0.5) → Dense64 → Dense10(softmax)
CIFAR：  Input(32,32,3) → Conv32(same) → Pool → Conv64(same) → Pool
         → Conv64(same) → Pool → Flatten → Dropout(0.5) → Dense128 → Dense10(softmax)
```

- **Flatten**：三维特征图拉平成一维，桥接到 Dense（Dense 只吃一维输入）。
- **加第三个卷积块而不池化**（MNIST 版）的用意：先压到 (3,3,64)=576 维，避免 Flatten 后全连接层吃 1600 维、参数量翻倍。

### 9. 编译与训练

```
优化器   Adam
损失     sparse_categorical_crossentropy（多分类 + 整数标签，配 softmax）
指标     accuracy
训练     batch_size / epochs / validation_split（从训练集切验证集，不动测试集）
```

### 10. 评估与可视化

```
evaluate    测试集算 loss / accuracy（只评估一次）
逐类准确率   mask 出每个类别，看“哪个数字/哪类最容易认错”
训练曲线    训练 vs 验证的 loss / accuracy
抽样预测    随机抽 10 张，预测对绿标题、错红标题
```

### 11. CIFAR-10 的难度预期

```
彩色、目标形态多变、类间相似（猫狗常互认错）
准确率 70% 左右就是正常水平，不能拿 MNIST 的 99% 来对标
所以轮数要给够（MNIST 5 轮、CIFAR 30 轮）
```

### 12. prepare_data.py 的设计（数据准备脚本）

```
用配置表描述 MNIST / CIFAR10 的差异（loader、图像形状、通道、类别名、文件名前缀）
统一流程：下载 → 拍平多余维度 → 断言校验（形状/类型/标签范围）→ 打印类别均衡 → 存 npz
关键取舍：保存原始 0~255 像素，归一化留到训练脚本里做，便于自由调整预处理
```

## 易错点 / 常见坑

| 坑 | 说明 |
|---|---|
| 忘记归一化 | 像素不缩到 [0,1]，梯度尺度混乱、训练不稳 |
| 忘记加通道维 | MNIST 是 (N,28,28)，必须补成 (N,28,28,1) 才能进 Conv2D |
| 用测试集调参 | 测试集只在最后评估一次，训练期只用训练/验证集 |
| 损失与输出层错配 | softmax 输出配 `sparse_categorical_crossentropy` |
| 层数乱堆 | 尺寸会一路缩到 1×1，空间信息丢失；用「尺寸倒推法」 |
| 拿 MNIST 99% 比 CIFAR | 两者难度不可比，CIFAR 70% 已经不错 |
| 彩色图用 `cmap='gray'` | 彩色 `imshow` 不能加 `cmap`，也不用 reshape |
| `.mat` 与 npz 图像方向不同 | `.mat` 列优先展平需转置；npz 存的已是正常形状 |
| 通道数与图片通道混淆 | 第二层起输入通道由上一层 filters 决定，与原始图片通道无关 |
